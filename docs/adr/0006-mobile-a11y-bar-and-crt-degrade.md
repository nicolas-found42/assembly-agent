# Mobile accessibility bar and CRT degrade path

ASM Agent's CRT identity (scanlines, flicker, VT323, amber) is hostile to mobile and assistive tech, yet it is the product. We need a defensible, GH Pages-compatible bar that preserves identity. We adopt **WCAG 2.2 AA** as the claim, **360px Android Chrome + 375px iPhone Safari** as first-class mobile (320px verified, desktop primary), a six-clause done-bar (zero axe critical/serious across 375/320/1280 + full keyboard operability including the brand toggle + `--amber-dim` ≥4.5:1 + `prefers-reduced-motion` kill-switch + decoupled `role="status"`/`role="log"` streaming + all 16 findings resolved/deferred), and keep the CRT effects by default while degrading gracefully under `prefers-reduced-motion: reduce` (disable `flickerAnim` 4s / `spinframes` 0.8s / cursor blink / boot and drawer transitions, replace spinners with static glyphs). Dependencies remain **Inclusion Checklist-gated** (license OSI/CC0/ODbL, CORS `*` via `curl -I`, keyless, ToS allows anonymous client fan-out, live `*`, GH Pages–compatible, no API key/cost) with vanilla as default; any awesome-list candidate must pass the checklist plus a live `100dvh`/`visualViewport` check before it ships.

Status: accepted
Considered Options: AAA or redesign palette (rejected — cost without legal gain and loss of identity); iPhone-only matrix (rejected — misses Android `visualViewport` quirks); blanked vanilla-only deps (rejected — excludes viable CDN a11y helpers that pass the checklist).
Consequences: HUD/overlay CSS moves to `100dvh` + `env(safe-area-inset-*)` + `visualViewport` for the composer; `#sidebar`/`#inspector` gain `100vw` reflow and focus trapping; contrast bump is a variable change (`#7a5200` → `#b87b00`/`#c28200`).
