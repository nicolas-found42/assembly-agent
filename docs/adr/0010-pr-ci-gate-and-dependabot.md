# PR CI gate and Dependabot

All changes to `main` go through feature-branch pull requests. Branch protection on `main` requires a PR (zero required approvals — solo maintainer), requires the `build-and-test` check from `.github/workflows/ci.yml` to pass, and includes administrators so the gate binds the owner too. CI runs the required gate (`npm run verify`, ADR 0013) for every PR to `main` in one workflow; the Pages publication is a separate job in that workflow which consumes the verified artifact and never rebuilds it (ADR 0014). The repository setting "automatically delete head branches" removes feature branches on merge. Dependabot version-updates both dependency surfaces — the pinned GitHub Actions and the npm lockfile (runtime and tooling grouped separately) — every day at 04:00 `America/New_York` using the `cron` schedule (`0 4 * * *`); the hosted service runs automatically shortly after `dependabot.yml` lands on `main` (there is no REST trigger endpoint — the Dependabot API covers alerts/secrets/repository-access only), and `dependabot-cli` can reproduce a job locally for debugging (reports findings; it does not create PRs).

Status: accepted
Considered Options: repository rulesets instead of classic branch protection (rejected — no benefit at single-branch scale, more moving parts); `schedule.interval: daily` (rejected — Dependabot "daily" runs Mon–Fri only, not every morning); third-party enforcement actions from awesome-actions such as branch-protection-bot/autosquash (rejected — they exist to toggle or bypass protections, the opposite of this gate).
Consequences: every change costs one PR plus a ~1 minute CI run; merged branches disappear immediately, so run `git fetch --prune` after pulling; `required_status_checks.strict` stays off so stale branches merge on their own green merge-ref CI run instead of demanding an update-branch loop; Dependabot opens PRs for the pinned actions and for npm minor/patch bumps (a semver-major npm bump arrives ungrouped) at most a few times a month, and those PRs must also pass the CI gate before merging.
